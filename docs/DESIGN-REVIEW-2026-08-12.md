# XClaw Design Review — 2026-08-12

> Independent 10-agent architecture review of `xclaw` @ `9c1f7a0`, judged against the question: **"is this design 1 year ahead?"** — i.e. against a projected **August 2027** industry bar.
> Method: 8 subsystem reviewers + 1 adversarial reality-check (ran the test suite, measured line provenance, audited git history) + 1 industry-trajectory calibrator, all benchmarked against reverse-engineering studies of Claude Code v2.1.170, OpenClaw, OpenAI Codex CLI, and Hermes. Every claim cites file:line evidence.

## Headline verdict

**Not 1 year ahead. Mean maturity 4.2/10; roughly 6–9 months behind today's open-source frontier on execution, ~2 years off the Aug-2027 bar.** The README's hedge ("not one year ahead of the entire industry") is accurate. However, ~6 design bets ARE the right 2027 shape and are worth doubling down on — plan-fingerprint approval binding, receipts-as-gates, the context-economics pipeline, resumable-SSE attach, the ops blueprint, and role-based routing (see per-subsystem Strengths and the Recommendations at the end).

## Agent loop + tool orchestration
*Scope: (src/agent, src/agents, src/tools)*

**Scores:** maturity 5.5/10 · future-proof 4/10 · -5 months vs frontier

**Verdict:** No — this loop is not 1 year ahead; it is roughly half a generation behind today's frontier on the fundamentals while being ahead in two pockets. The token/cache economics pipeline (reversible offload, prefix-stability, pressure-adaptive eviction) and the receipt-backed DAG swarm are genuinely forward-looking and will still be the right shape in Aug 2027, but the skeleton they hang on — stateless one-shot runs with no conversation threading, strictly serial tool execution, no real streaming on Anthropic, and hardcoded 25/60-call ceilings that throw exceptions — is the shape of a 2024/2025 agent that a 2027-class model would be actively throttled by. To be 'ahead' it needs session transcripts as a first-class loop input, parallel concurrency-safe tool dispatch, progress-based (not count-based) breakers, and deletion of the regex intent/closure/suggestion heuristics the model now subsumes.

### Strengths
- Client-side context-economics pipeline is ahead of typical OSS: prefix fingerprint + per-turn drift assertion, cache breakpoints, pressure-adaptive eviction with dual-EMA and frozen rank sizes, and reversible tool-result offload (large results -> durable file + short handle the agent can re-read) plus extractive fold. This 'context as filesystem' direction is the same bet Claude Code made with microcompaction and ages well.
  - *Evidence:* `src/agent/loop.mjs:489-539, src/tokens/prefix-optimize.mjs, src/tokens/eviction.mjs:1-60, src/tokens/compaction.mjs:44-110 and 260-325, src/tokens/rank-size.mjs`
- Normalized toolTrace spine (status/outcome/artifacts/policy per call) feeding turn-state, receipts, metrics and suggestions — an observability layer most OSS agents lack and that survives model upgrades.
  - *Evidence:* `src/agent/tool-trace.mjs:1-120, src/agent/turn-state.mjs:48-140, src/agents/swarm-receipt.mjs`
- Original DAG swarm orchestration: id+dependsOn task graphs -> topological waves -> upstream handoff, git-worktree isolation per implement-role child, structured error codes with hints, receipts, voting, and merge gates. Claude Code's Task tool has no user-visible DAG; this is at-or-ahead of frontier for multi-agent structure. Browser-fabric role physics (actor needs tab_lease, critic approves commit_gate, observer read-only) is an original capability-based safety design.
  - *Evidence:* `src/agents/swarm-run.mjs:1-125 and 33-80, src/agents/spawn.mjs:133-167, src/agents/worktree.mjs, src/tools/browser-tools.mjs:686,745`
- Loop-guard detectors are evidence-based (ported OpenClaw, enabled by default unlike upstream): no-progress requires result-hash proof, ping-pong needs alternation + stable outcomes, argument churn needs stable-outcome variants — better than naive repeat counters, and pre-call detect + post-call record ordering is correct.
  - *Evidence:* `src/agent/openclaw-loop/detection.mjs:24, 91-158, 266-291; src/agent/loop.mjs:656, 916`
- Defense-in-depth per tool call in the right order: loop-guard -> approval gate (with pending-approval graceful stop) -> path sandbox -> execute -> truth-channel assert -> truncate -> record; provider failover chain + draft/act/verify role routing + Retry-After-aware decorrelated-jitter backoff throughout.
  - *Evidence:* `src/agent/loop.mjs:656-916, src/agents/swarm-run.mjs:299-380, src/agent/provider.mjs:100-110`
- Real test coverage of this subsystem: 200 test files including loop-guards, loop-guard-config, s1/s2/s3 swarm, compaction, turn-state, suggestions e2e.
  - *Evidence:* `test/ (200 files): test/loop-guards.test.mjs, test/s2-swarm-graph.test.mjs, test/compaction.test.mjs, test/turn-state.test.mjs`

### Weaknesses
- No conversation-history threading — the defining gap. runAgentLoop accepts only userMessage and builds messages=[system,user] fresh per inbound message; even webchat stores session.messages but never feeds them back. Every channel message is a stateless one-shot run. Claude Code, Codex, and OpenClaw all thread full session transcripts with compaction/resume; this has been table stakes since 2024. The elaborate eviction/compaction machinery only serves intra-run tool accumulation.
  - *Evidence:* `src/agent/loop.mjs:93-104, 426-429; src/channels/base.mjs:33-43; src/channels/webchat/index.mjs:136-166`
- Strictly serial tool execution with no concurrency-safety classification. Claude Code's eZH manager fans out safe tools in parallel and starts tools while the response is still streaming; Codex runs parallel via Promise.all with source-order results. A 2027 model emitting 10+ parallel calls will crawl here.
  - *Evidence:* `src/agent/loop.mjs:645 (for (const call of calls)); cc-study 02-agent-loop-turn-execution.md:104-110; codex-study 02-core-agent-loop.md:154`
- The global circuit breaker is a hard total-call ceiling, not a stuck-detector: it trips on history.length >= threshold, history is never reset on progress, and historySize is forced >= threshold — so prod caps every run at 25 tool calls and lab at 60 regardless of whether each call made progress. Claude Code has no total-call cap (turn cap only via env; its breakers are evidence-based).
  - *Evidence:* `src/agent/openclaw-loop/detection.mjs:85-87, 239-247; src/config/profiles.mjs:39, 80`
- Critical loop-guard stop exits by throwing out of runAgentLoop (try has no catch), skipping the entire post-run pipeline — turnState, suggestions, usage-ledger persist — and surfacing to channels as an exception rather than a graceful 'I got stuck' reply.
  - *Evidence:* `src/agent/loop.mjs:656-668 (throw), 484-968 (try/finally with no catch), 970-1113 (skipped pipeline)`
- Half-wired port: guard.record never passes details, so the ported exec exit-code hashing, write-unchanged outcome, and unknown-tool-repeat detection are dead code — the nuanced OpenClaw outcome semantics were copied but never activated.
  - *Evidence:* `src/agent/loop.mjs:916 (guard.record(name, args, text)), :656 (detect without opts); src/agent/openclaw-loop/detection.mjs:180-203, 249-264`
- Streaming exists only on the OpenAI-compat path; the native Anthropic provider's chatStream silently falls back to non-streaming chat, so no token streaming on the flagship provider and no tool-call-during-stream execution anywhere.
  - *Evidence:* `src/providers/anthropic-messages.mjs:349-350; src/agent/provider.mjs:164-338`
- Turn budgets are 2024-scale and scattered: maxTurns default 15 (one model call per 'turn'), subagents hard-capped at min(cfg,8), swarm roles at 4-8 turns, jobs resume by halving maxTurns. Raising headroom for long-horizon 2027 models requires touching many hardcoded numbers.
  - *Evidence:* `src/agent/loop.mjs:112; src/agents/spawn.mjs:160; src/agents/swarm-run.mjs:33-80; src/jobs/checkpoint.mjs:77`
- Tool dispatch is special-cased by name inside the loop (spawn/swarm/merge/recall/browser-hook if/else chains, tools re-instantiated per call) instead of a uniform tool interface with before/after hooks like Codex's AgentLoopConfig or CC's tool abstraction — adding a tool class means editing the loop.
  - *Evidence:* `src/agent/loop.mjs:796-880; codex-study 02-core-agent-loop.md:94,155`

### Bitter-lesson violations (scaffolding a 2027 model obsoletes)
- Hard tool-call-count circuit breaker (prod 25 / lab 60 / default 30) with no progress-based reset — a quantity cap that throttles exactly the long-horizon competence 2027 models will have (src/config/profiles.mjs:39,80; src/agent/openclaw-loop/detection.mjs:21,239-247)
- inferGoal: regex classification of user intent into test/fix/ship/implement/question (src/agent/turn-state.mjs:14-42)
- detectTurnClosure: regex 'continuation language' detection ('next I'll', 'TODO', 'in progress') to decide if a turn is done (src/agent/suggestions.mjs:152-190)
- 816-line handcrafted follow-up-suggestion engine with CTR bias priors and chip templates — a 2027 model generates better follow-ups natively (src/agent/suggestions.mjs + src/agent/suggestion-feedback.mjs)
- collectArtifacts: regex path-scraping from tool result text to guess touched files (src/agent/tool-trace.mjs:74-84)
- isKnownPollToolCall: hardcoded tool-name list for poll semantics instead of tool-declared metadata (src/agent/openclaw-loop/call-kind.mjs:9-20)
- Extractive keyword summary as the only wired compaction fold — summarizeFn (LLM summarization) exists but is never passed by the loop or config plumbing (src/tokens/compaction.mjs:113-160, 328-341; src/agent/loop.mjs:528-539)
- normalizeTool / normalizeToolFamily name-substring heuristics for tool families (src/agent/truncate.mjs:84-92; src/agent/tool-trace.mjs:18-27)
- Bespoke claims/evidence JSON protocol hardcoded in the base system prompt instead of native structured outputs (src/agent/loop.mjs:67-82)
- Swarm role promptPrefix strings (research/implement/verify/critic) — prompt-chain role scaffolding with per-role hardcoded turn budgets (src/agents/swarm-run.mjs:33-80)

## GATEWAY + API + AUTH/OAUTH + SESSIONS/SEATS/TOKENS
*Scope: (src/gateway, src/auth, src/sessions, src/seats, src/tokens[gateway-facing], src/pairing, ui/)*

**Scores:** maturity 4.5/10 · future-proof 4/10 · -8 months vs frontier

**Verdict:** No — this subsystem is not one year ahead; on its core job (being an authenticated multi-client boundary) it is meaningfully behind today's OpenClaw-class frontier, which already ships scoped operator roles, device auth, pre-auth budgets, and rate limits where xclaw has one static default-open token and an unauthenticated WebSocket. Two pieces are genuinely early — resumable SSE/NDJSON streams with attach-to-inflight-run, and queueing-theory admission control — and those bets will still look right in August 2027. But the single-process JSON-file state, absent identity/scopes/versioning, and Claude-Code-impersonation OAuth mean the 2027-correct shape requires re-architecting the auth and state planes, not iterating on them.

### Strengths
- Resumable streaming is genuinely ahead of the OSS frontier: monotonic event IDs, Last-Event-ID replay, attach-to-in-flight-run (resume-live), replay-only for finished runs, and a dual SSE/NDJSON writer negotiated via Accept/?format — applied uniformly to agent, swarm, and webchat streams. Claude Code's SSE pipeline has no server-side resume (cc-study/12-streaming-sse-pipeline.md) and OpenClaw does run-buffer replay only over its WS protocol. Durable/resumable HTTP agent streams are exactly where the industry is heading by 2027.
  - *Evidence:* `src/gateway/stream-resume.mjs:121-206 (StreamEventLog), :247-303 (resolveStreamResume modes), src/gateway/sse.mjs:145-153,174-180 (NDJSON negotiation), src/gateway/index.mjs:199-287 (agent resume paths); e2e-tested in test/stream-resume-e2e.test.mjs`
- Queue backpressure is designed from queueing theory, not vibes: Erlang-A/Halfin-Whitt QED staffing (c ≈ a + β√a), finite buffer with rejected_full, deterministic patience (maxWait abandonment), live metrics broadcast, and an operator endpoint that computes suggested concurrency from measured arrival/service rates. No OSS agent gateway studied has this.
  - *Evidence:* `src/utils/admission.mjs:19-24 (qedStaffing), :104-117 (tryAdmit); src/jobs/queue.mjs:84-110 (enqueue admission); src/gateway/index.mjs:1174-1199 (/queue/admission suggest)`
- OAuth token lifecycle fundamentals are near Claude Code parity: PKCE S256, single-flight per-app refresh with refresh-token rotation and invalid_grant reuse-detection clearing, proactive refresh scheduler with 10-min skew, optional AES-256-GCM at-rest encryption, 0o600 file modes, and a cross-process wx-lockfile around auth-profile writes (CC's .oauth_refresh.lock analogue).
  - *Evidence:* `src/auth/anthropic-oauth.mjs:48-54; src/connected/token-refresh.mjs:1-38 (single-flight + rotation + reuse detection); src/connected/refresh-scheduler.mjs:44; src/connected/token-crypto.mjs:20-33; src/auth/profiles.mjs:28-48 (file lock)`
- Session keying adopts OpenClaw's proven canonical scheme (agent:channel:peerKind:peerId:thread with normalize/parse round-trip), keeping channel-agnostic routing that will still be the right shape for multi-channel agents in 2027.
  - *Evidence:* `src/sessions/session-key.mjs:31-101 (build/parse/normalize); src/sessions/router.mjs:56-134 (bindings); THIRD_PARTY.md attribution`
- Ops surface is real: readiness gated on computer health + queue depth for LBs, graceful shutdown with queue drain and SIGHUP soft config reload, Prometheus gauges for the stream registry, and 200 test files including gateway-auth, seats, admission, and stream-resume e2e coverage.
  - *Evidence:* `src/gateway/readiness.mjs:12-56; src/gateway/index.mjs:2367-2396; src/gateway/stream-resume.mjs:390-417; test/ (200 files, incl. stream-resume-e2e.test.mjs, gateway-auth-p4.test.mjs, seats.test.mjs, admission.test.mjs)`

### Weaknesses
- The auth model is a single static shared token with zero identities, scopes, or roles — and it is deny-list default-OPEN: only enumerated path prefixes are protected, so every route not in the handcrafted list (/media/*, /alerts/*, /tokens/*, /events/*, /checkpoints, /webhooks/pagerduty/recent) ships unauthenticated even in strict mode. The token is also accepted via ?token= query param (log leakage) and compared with === instead of timingSafeEqual. OpenClaw's gateway — today's frontier — has operator scopes, operator-vs-node roles, device tokens with signed payloads, per-IP pre-auth connection budgets, and control-plane write rate limits (openclaw-study/02-gateway-server.md).
  - *Evidence:* `src/gateway/auth.mjs:57-106 (protect list = allowlist of protected prefixes, everything else open), :116-122 (query-param token), :124 (non-constant-time compare); zero grep hits for timingSafeEqual in src/gateway+src/auth`
- The WebSocket hub /ws/events performs no auth at all on upgrade — any local-network client can subscribe and receive admission/queue/eviction/swarm telemetry — and it is a hand-rolled RFC6455 implementation without client-mask enforcement, fragmentation, or close handshake. Combined with Access-Control-Allow-Origin: * on every response (including authenticated JSON and SSE), the browser-facing security posture is below 2025 baseline, let alone 2027.
  - *Evidence:* `src/gateway/ws-hub.mjs:157-203 (upgrade path, no token check), :20 (module-global clients Set); src/gateway/index.mjs:119 and src/gateway/sse.mjs:19 (CORS wildcard)`
- The router is a 2,399-line if-chain with ~90 inline routes and three near-identical ~250-line copy-pasted stream handlers, and it contains a live copy-paste bug: the startup SLO-monitor/approval-digest block is duplicated inside the POST /queue handler, so every enqueue re-runs startSloMonitor and can register an extra digest setInterval (timer leak). No method registry, no scope table, no route-level middleware — contrast OpenClaw's descriptor registry (name→scope/startup/write policy) dispatching ~200 methods.
  - *Evidence:* `src/gateway/index.mjs:1239-1254 (duplicated startup block inside POST /queue), :187-367 vs :376-679 vs :682-870 (triplicated stream handlers), :1035-2332 (if-chain)`
- No API versioning of any kind: no /v1 prefix, no version negotiation header, no deprecation mechanism — only an informational /version endpoint. Event payload shapes (result/lifecycle/error) are ad-hoc per handler. Any 2027 client ecosystem talking to this gateway has no compatibility contract.
  - *Evidence:* `src/gateway/routes-map.mjs:4-59 (full route list, zero versioned paths); grep for v1 in gateway yields nothing route-shaped`
- Backpressure exists only on the /queue path. /agent/run, /agent/run/stream, /swarm/run, and all webchat routes invoke runAgentLoop/runSwarmFanOut directly with unbounded concurrency, no admission, no rate limiting anywhere in the gateway (zero 429 emitters), and an unbounded readBody (no size cap) on every JSON route except the PagerDuty webhook. One hostile or buggy client can fork unlimited concurrent agent loops.
  - *Evidence:* `src/gateway/index.mjs:1822-1852 (/agent/run direct), :1855-1872 (stream direct), :124-130 (readBody no limit) vs :1056 (only pagerduty limited); grep rateLimit|429 in src/gateway = 0 hits`
- The entire state layer is single-process JSON-on-disk with races: sessions live in module-level Maps with a 200ms debounced write (crash window, no TTL/eviction, unbounded growth); the seats ledger does read-modify-write with no lock and non-atomic writeFile (concurrent requests lose spend records — a budget enforcement mechanism that can be raced); the stream-resume registry is in-memory only, so resume dies on restart and can never work behind a load balancer. There is no multi-instance story anywhere.
  - *Evidence:* `src/sessions/router.mjs:17-36 (Maps + debounce); src/seats/manager.mjs:54-66 (no lock, direct writeFile), :99-122 (RMW race); src/gateway/stream-resume.mjs:50 (in-memory registry)`
- The 'multi-seat model' is budget accounting, not tenancy: seat identity derives from unauthenticated channel-supplied peer metadata (channel:id string), is not bound to any authenticated principal (there is only one shared gateway token), so any caller can claim any seat or the 'default' seat. It caps spend per claimed label, it does not isolate users.
  - *Evidence:* `src/seats/manager.mjs:25-31 (peerKey from peer object), :36-52 (resolveSeat trusts key); src/gateway/auth.mjs:6-12 (single token, no principal to bind to)`
- Roughly a third of src/auth is dead weight or unreachable ceremony: cose-sign1-verify, cose-es256-verify, cose-key, cookie-flags, secure-inject, idempotency, and pkce.mjs are imported by nothing outside src/auth; webauthn, web-login, key-rotation, key-compromise-playbooks, and jwks-redis-pubsub are CLI-only. The gateway serves JWKS endpoints and invalidation epochs, yet no gateway route authenticates via JWT — public keys published for a verifier that doesn't exist. This inflates the apparent security posture far beyond what a request actually encounters (a single string compare).
  - *Evidence:* `import-graph grep (2026-08-12): auth/{cose-*,cookie-flags,secure-inject,idempotency,pkce} = 0 imports outside src/auth; src/gateway/index.mjs:1417-1450 (JWKS ops routes) with no JWT verification on any request path`
- Anthropic access is built on impersonating Claude Code: hardcoded Claude Code public client_id, spoofed 'user-agent: claude-code/2.1.226', and forced injection of the exact 'You are Claude Code…' system attestation string that Anthropic gates OAuth inference on. This is an actively-countered cat-and-mouse dependency with ToS risk, and it carries no SCAFFOLD marker despite being the definition of scaffolding (0 SCAFFOLD markers in the whole subsystem).
  - *Evidence:* `src/providers/anthropic-oauth-headers.mjs:11-13 (OAUTH_ATTESTATION), :29 (spoofed UA); src/auth/anthropic-oauth.mjs:29 (CLAUDE_CODE_CLIENT_ID); grep SCAFFOLD in subsystem dirs = 0`
- Token-store encryption key is a single unsalted SHA-256 of the gateway bearer token (min 8 chars accepted, no KDF), meaning the same secret that authenticates every API request also decrypts all provider refresh tokens at rest — one leak compromises both planes. Shipped UIs are inconsistent with the auth design: ui/webchat sends no token, so enabling gateway auth in strict mode 401s the product's own chat surface.
  - *Evidence:* `src/connected/token-crypto.mjs:10-18 (sha256(gateway token), length>=8); ui/webchat/app.js:171-173 (no Authorization header) vs src/gateway/auth.mjs:95 (/channel/ protected in strict mode)`

### Bitter-lesson violations (scaffolding a 2027 model obsoletes)
- Claude Code identity spoofing for OAuth inference (src/providers/anthropic-oauth-headers.mjs:11-35 + src/auth/anthropic-oauth.mjs:29): handcrafted mimicry of a specific client build string and system-attestation prefix, verified-live against a gate Anthropic actively maintains. By mid-2027, first-class agent identity/delegated-auth (or a rotated gate) makes this dead code at best, a ban at worst. Unmarked scaffolding.
- Handcrafted path-prefix auth classification (src/gateway/auth.mjs:57-106): every new route requires manually extending the protected-prefix list, and forgetting means default-open. A default-deny policy engine (or capability tokens) removes the per-route human heuristic entirely.
- Per-channel case-preservation special-case table in session keys (src/sessions/session-key.mjs:18-22: signal:group→'segment', matrix:*→'tail') — inherited OpenClaw special-casing baked into the key grammar.
- Chars-per-token calibration heuristics run at gateway startup (src/gateway/index.mjs:1007-1030 probeTokenizerRuntime → proseCharsPerToken/codeCharsPerToken curve fitting; src/tokens/probes.mjs): estimating tokenization by character-class ratios is scaffolding around missing provider counting; 2027 providers return exact usage and server-side counting endpoints.
- Pasted-code OAuth flow with CODE#STATE hand-parsing (src/auth/anthropic-oauth.mjs:130-150) as the primary login path — copy-paste-console scaffolding around the absence of a first-class redirect/device flow.
- Weight-tuned eviction knobs surfaced through the gateway event stream (src/gateway/index.mjs:160-185 exporting wSize/wAge/pressure/skew/deadband EMA tuning): hand-tuned context-eviction weighting that a 2027-class model with native long-context management and provider-side caching makes unnecessary.

## SECURITY MODEL
*Scope: (approval gate, frozen systemRunPlan TOCTOU binding, plan fingerprint observability, tool/exec allowlists, lab/dev/prod profiles)*

**Scores:** maturity 3.5/10 · future-proof 4/10 · -9 months vs frontier

**Verdict:** The one original idea — binding an async human approval to a frozen, fingerprinted execution plan and revalidating before release — is genuinely the right shape for August 2027, when gateway agents will routinely hold approvals open for minutes-to-hours; none of CC/Codex/OpenClaw have that primitive today. But at HEAD it is unenforced theater: the executed command is the raw string through unsandboxed /bin/bash -lc with the full secret-bearing environment, the pinned exe never reaches the spawn, the SLA path skips revalidation, the observability PR is dead code in the live loop, and the flagship test file does not even import. By 2027 the winning stack is hash-bound approvals enforced at spawn inside an OS-level sandbox with model-based command judgment and durable trust accumulation — xclaw has sketched the first layer and is 9+ months behind today's frontier on every other one.

### Strengths
- Original, well-motivated TOCTOU concept: freeze argv/cwd/exe (+ optional file hashes) into a fingerprinted plan BEFORE the human decision, revalidate realpaths/hashes on approve. This is xclaw-original design (grep of /root/openclaw-study/reverse-eng finds zero 'runPlan' mentions; CC and Codex studies show no post-approval revalidation either) and it is the right primitive for a chat-ops gateway where approvals arrive minutes later over Telegram, unlike interactive-local CLIs.
  - *Evidence:* `src/security/system-run-plan.mjs:95-190 (buildSystemRunPlan), :223-275 (revalidatePlan drift checks); src/security/approvals.mjs:182-192 (freeze before pending visible), :270-285 (revalidate on decide)`
- Sane fail-closed knobs with secure sub-defaults inside the gate: bindSystemRunPlan and revalidateOnDecide default ON, requirePinnedExe opt-in fail-closed when the exe cannot be realpath'd, and the doctor audit surfaces every weakening (bindSystemRunPlan=false, autoApprove, prod+autoApprove=error).
  - *Evidence:* `src/security/approvals.mjs:93-97; src/security/system-run-plan.mjs:180-187; src/security/audit.mjs:53-85`
- Async-operator observability is genuinely forward-shaped: pending list carries sanitized plan + fingerprint + SLA age/deadline, and an approval digest pushes aged pendings to chat channels — a remote-operator UX that interactive CLI frontiers do not need but 2027 gateway agents will.
  - *Evidence:* `src/security/approvals.mjs:306-330 (listPending with plan/fingerprint/remainingMs); src/security/approval-digest.mjs:7-52`
- Clean control-plane/capability-plane articulation: the gateway owns approval decisions, the computer plane owns execution; pure-function plan module with no process-global state.
  - *Evidence:* `src/security/system-run-plan.mjs:12-16 (design-goal comment honored — module is pure); src/gateway/routes/security.mjs:9; src/computer/modules/bash-tool.mjs (separate plane)`
- Per-peer workspace isolation checks for multi-tenant chat bindings (distinct-root validation, cross-peer path resolution denial) — a multi-user concern OpenClaw-class gateways handle but single-user CLIs ignore.
  - *Evidence:* `src/security/workspace-isolation.mjs:22-60`

### Weaknesses
- The frozen plan is never enforced at execution — it is observability cosplaying as enforcement. After approval the loop executes the ORIGINAL args via computer.callTool, and the computer plane spawns /bin/bash -lc <raw command string> with env: process.env. The pinned exe realpath has no relationship to what bash's PATH resolution actually runs; -l even sources login profiles. Approved argv/exe pins are dropped on the floor.
  - *Evidence:* `src/agent/loop.mjs:869-878 (computer.callTool(sessionId, name, args)); src/computer/modules/bash-tool.mjs:38,58 (spawn('/bin/bash', ['-lc', command], { env: process.env }))`
- TOCTOU window narrowed, not closed: revalidatePlan runs at decide() time in the gateway process, but the spawn happens later on the computer plane — a symlink swap between decide and spawn still wins. And the fingerprint recheck is tautological: it recomputes the hash over the same in-memory object, so it can only catch memory mutation, never filesystem drift.
  - *Evidence:* `src/security/approvals.mjs:270-285 (revalidate at decide only); src/security/system-run-plan.mjs:264-272 (planFingerprint(plan) over same object)`
- The SLA auto-approve path — the path with the LONGEST time-of-check-to-time-of-use gap — resolves ok:true with zero revalidation, bypassing the entire TOCTOU mechanism the PR exists to provide.
  - *Evidence:* `src/security/approvals.mjs:42-50 (slaAction!=='deny' resolves approved without revalidatePlan)`
- PR #5 (plan fingerprint observability) is dead code in the live path: src/agent/secure-tool-call.mjs is imported ONLY by its own test; loop.mjs calls the gate directly and its approval_required events and toolTrace policy objects omit planFingerprint/plan entirely.

## The August-2027 bar

### Table stakes by Aug 2027
- MCP-native everything: first-class MCP client AND server with OAuth/PKCE remote transports, registry-based discovery, elicitation, and deferred/lazy tool loading (ToolSearch-style) so hundreds of tools never sit in the prompt. By Aug 2027 a gateway whose integrations are bespoke per-service adapters instead of MCP surfaces is simply not evaluated.
- OS-level sandboxing by default for every execution path: bwrap+seccomp or microVM (Firecracker/gVisor-class) per run, plus a DNS-pinned SSRF egress perimeter with an unconditional cloud-metadata block floor and fail-closed headless behavior. Hermes-style 'the OS is the only boundary, and we don't use it' and OpenClaw-style in-process unsandboxed plugins are disqualifying by 2027.
- Durable, crash-resumable long-horizon runs: append-only event-sourced transcripts (JSONL + derived index, 'SQLite never leads JSONL'), checkpoint/resume journals with exactly-once phase replay (CC's SHA-256 workflow journal), interrupted-turn recovery, and session DAG branching. Multi-day tasks that survive process death are the baseline expectation, not a differentiator.
- Multi-agent orchestration as a built-in primitive: parallel subagent spawn with explicit concurrency/residency limits and RAII-style slot accounting (Codex), fork-mode context filtering, steering/follow-up queues, worktree isolation, and an operator-facing fleet view to attach/steer/kill any running agent. One-serial-agent architectures read as 2025-era.
- Disciplined two-tier context lifecycle: byte-stable cached system prompt with cache_control breakpoints, ephemeral context injected into user messages, zero-cost microcompaction of stale tool outputs, full compaction with live-file re-injection, and token accounting from model-reported usage. This was the CC/Hermes consensus gap in 2026; by 2027 it's plumbing every serious gateway has.
- A composable layered policy engine: managed/org > user > project > session precedence where lower layers can only restrict, never grant (Codex Constrained<T> / requirements.toml); deny-first rules; capability ceilings on MCP servers and plugins (effectiveMaxPermission); static AST fast-path classifier with cheap-model escalation only for ambiguous actions.
- Per-agent/per-task/per-seat metering with hard budget enforcement: every tool call and token attributed to a run, real-time cost ledgers, spend caps and kill-switches, and exportable usage reports. Self-hosted deployments are bought by orgs in 2027, and orgs do not deploy agent fleets they cannot meter.
- Signed supply chain end-to-end: sigstore/OIDC provenance-attested releases, SBOMs, digest-pinned bases, and — critically — signed plugins/skills with manifest-first activation (config/onboarding/trust decisions made before any plugin code executes, OpenClaw-style). An unsigned skill marketplace is a liability, not a feature, by Aug 2027.
- Standards-compatible skills and agent-curated memory: SKILL.md/agentskills.io-compatible skill format with progressive-disclosure indexes, plus a memory loop with scheduled consolidation ('dreaming'/Curator), archive-never-delete safety, and explicit anti-poisoning rules (never persist negative tool/environment claims). Project-scoped memory, not one global blob (Codex's known gap).
- One versioned, schema-validated wire protocol serving all clients: typed frame envelope, protocol version, replay-resistant device auth (Ed25519 challenge-signing), codegen to every client platform — with web/TUI/mobile/messaging channels and browser/computer-use control all riding the same control plane as thin plugin adapters.

### What would make a project genuinely AHEAD in Aug 2027
- Verifiable action receipts: a hash-chained, signed, independently replayable ledger of everything an agent did — tool calls, diffs, network egress, spawned children — portable across trust boundaries ('here is cryptographic proof of what my agent did to your system'). All four 2026 systems logged; none proved. The project that ships receipts as a product surface owns the enterprise conversation in 2027.
- Closed-loop self-improvement with training-grade data: the gateway doubles as its own data factory — hermetic trajectory capture (no operator-state leakage), outcome-labeled tool-call datasets, and an in-product path to fine-tune/RL a local specialist or distill routing policies from your own usage. Hermes was the only 2026 system pointing here; done rigorously it compounds and cannot be copied by a feature checklist.
- Cross-gateway agent-to-agent federation: your agent securely delegates work to someone else's agent/gateway over an open A2A-descendant protocol with scoped capability grants, verifiable device identity, and receipts that cross the trust boundary. Every 2026 system was an island; the first credible multi-party delegation story defines the category's next phase.
- Machine-checkable containment: declarative per-task policy (filesystem, egress, secrets) compiled down to OS-enforced primitives (microVM + seccomp + eBPF) and verified against the spec — so a fully prompt-injected agent provably cannot exfiltrate, and you can show the proof. This upgrades 2026's honest-but-manual 'the OS is the boundary' posture into an auditable guarantee.
- Cost-aware market-style orchestration: agents hold budgets and every subtask is routed across a model portfolio by live price/latency/capability bidding, with automatic escalation on failure and outcome-based (per-completed-task) accounting — replacing both static model pinning and hand-wired cheap-model special cases with a single economic policy layer.

### Popular 2026 patterns that will look obsolete
- Handcrafted prompt-chain / rigid DAG workflow frameworks (LangChain-chain style): models plan their own decomposition by 2027; the durable value migrates to checkpoint/resume journals and budget enforcement, not human-authored choreography. CC's workflow system survives only because its core is the resume journal, not the DSL.
- Hand-tuned per-channel reply heuristics: OpenClaw's ~3k-line auto-reply dispatch body and Hermes's 1100-line issue-number-scarred _handle_message are peak 2026. Mention-gating regexes, debounce trees, and directive short-circuits get replaced by a cheap-model admission call over a thin, generic channel I/O seam.
- Static tool catalogs baked into the system prompt: obsoleted twice over — by deferred tool loading (ToolSearch) and by code-over-RPC execution (Hermes execute_code/PTC), where the model writes one script that calls N tools and only stdout returns. Prompt-resident 50-tool menus are a token bonfire.
- 30KB handcrafted safety-classifier system prompts and regex/prefix allowlist gardens as the primary exec policy: the ban lists survive (they encode red-team knowledge), but the elaborate rule prose gets replaced by cheap fast models doing semantic judgment over an AST fast path. Codex's Starlark DSL is the sophisticated version of a dying species.
- Per-command human approval as the primary safety mechanism: approval-fatigue UIs don't scale to fleets of background agents. Superseded by sandbox-by-default + restrict-only policy layers + post-hoc verifiable receipts; the human moves from gatekeeper-per-command to auditor-per-run.
- 20-backend provider adapter matrices and OpenAI-facade shims (Hermes's ProviderTransport + 5.9K-LOC duplicate auxiliary client): provider convergence on a handful of standard wire APIs plus gateway-level routing makes hand-maintained adapter zoos dead weight. Keep one normalization seam and a provider_data passthrough; delete the rest.
- Bespoke embedding/vector-RAG pipelines as the primary personal-memory system: agent-curated file-based memory with scheduled consolidation, huge model contexts, and platform-native retrieval beat hand-rolled chunk-embed-rerank stacks for the gateway use case. Vector search demotes to one index behind a memory tool, not the architecture.
- Client-side tokenizer accounting and hand-tuned truncation thresholds: model-reported usage plus provider-side context management (server-side compaction, 1M+ windows) turn elaborate local token-budget machinery into scaffolding. Microcompaction of stale tool outputs survives; the hand-calibrated summarize-at-N heuristics do not.
- In-process unsandboxed plugin execution with 'trust = the operator installed it' (Hermes exec_module, OpenClaw native plugins): manifest-first activation plus WASM/subprocess/microVM plugin isolation becomes mandatory, and the 2026-era in-process convenience model reads as negligent.
